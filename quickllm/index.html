◈QuickLLM

A complete generative AI suite on a single 8 GB GPU

Text, images, video, 3D models and music. QuickLLM swaps models in and out of memory based on each request and runs entirely on two home machines, with no cloud services.

The problem

One GPU, one model at a time

The language model that drives the chat and the models that generate images, video, 3D and music don't fit in 8 GB of VRAM together: switching means unloading one and loading the other from disk, and every swap takes tens of seconds. If a request for four images bounced between them after each image, the wait would multiply. QuickLLM collects all the work first and swaps models only once.

Step 1 Plan The local LLM reads the request and produces a JSON plan: what to generate, how many times, with which prompt.
Step 2 Free the VRAM Jobs go into a single queue and the LLM is unloaded from memory only once.
Step 3 Generate ComfyUI runs images, video, 3D and music in sequence while the chat waits its turn.
Step 4 Reload Once the queue is empty, the LLM returns to memory and the conversation picks up where it left off.

Only one model in memory at any time.

Features

Beyond generation

agent mode

Writes, runs and publishes code

A ReAct agent creates files, edits them, runs them in an isolated sandbox and fixes errors until the task is done.

  • code execution in dozens of languages with Piston
  • generated websites published in one click
  • video games built by the same engine
RAG

Answers from your documents

Uploaded PDFs are split into chunks, embedded locally and searched by similarity. Answers cite their sources.

  • embeddings with EmbeddingGemma, no external services
  • pre-indexed documentation collections
  • web search when the documents aren't enough
Under the hood

The choices you don't see

Part of the work never shows up on screen: it's what keeps the system running when requests pile up, when a release goes wrong or when someone tries to use it without permission.

Planner
Decides before it answers Before the visible reply, the model produces a JSON plan of the actions to run: generations, web searches, virtual machines. Separating the decision from the answer makes even a small model reliable.
Shared GPU
Never two models at once While ComfyUI is generating, the backend rejects text requests with 503 and Retry-After, and the client retries on its own. It's mutual exclusion between two processes on two different machines.
Releases
A safety net A production deploy only starts if staging is green on the same commit. Before updating, it backs up the database and records the restore point for rollback.
Access
No forgotten routes Every backend route must declare its access level: if it's missing, the server won't start. Automated tests try to get in without credentials and with tampered paths.
Costs
A budget in euros of electricity Each IP has a daily budget based on real power consumption: GPU watts times generation time. Past the limit, requests are paused until the next day.
Environments
Truly isolated staging The beta has its own database, configuration and branch, and is reachable only through the VPN: from the local network the port doesn't respond at all.
Infrastructure

Two machines, two environments

The application layer and the GPU work live on separate machines, connected through a VPN. Production and staging are isolated, and every release goes through tests before reaching users.
